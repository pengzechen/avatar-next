# Phase 2 VMM 实现文档

## 概述

本次提交实现了 AArch64 VHE（Virtualization Host Extensions）虚拟机监控器（VMM）基础设施，
并以"三特权级并发循环"为验收测试：EL2 内核线程、EL1 Guest vCPU 线程、EL0 用户进程同时无限运行。

---

## 架构设计

### 核心模型：vCPU = task，VM = process

| 概念   | Avatar OS 对应 | 说明                             |
|--------|---------------|----------------------------------|
| VM     | `vm_t`        | 静态分配，包含 cfg + vcpu 数组   |
| vCPU   | `vcpu_t`      | 每个 vCPU 对应一个内核 `task_t`  |
| 调度   | 现有 sched    | vCPU 任务与普通内核任务混合调度  |

### VHE 工作原理

系统运行在 EL2（`HCR_EL2.E2H=1`，VHE 模式）。

```
Host 内核 (EL2)
    ├── el2_loop 线程   (EL2 kernel task，task_yield 协作)
    ├── vcpu0 线程      (EL2 kernel task，运行 VMM 主循环)
    │       └── [el2_enter_guest] ──► Guest EL1 执行
    │               [el2_trap_exit] ◄── WFI/HVC 陷入
    └── el0_loop 进程   (EL0 用户进程，SVC 系统调用，时钟抢占)
```

进入/退出 Guest 的 HCR_EL2 状态机：

| 状态      | TGE | VM | TWI |
|-----------|-----|----|-----|
| Host 模式 | 1   | 0  | 0   |
| Guest 模式 | 0  | 1  | 1   |

## 新增文件

### include/vmm.h
VMM 公共类型和 API 头文件。`vcpu_t` 前部字段固定偏移（与汇编 `VCPU_*` 宏严格对齐）：

| 宏               | 偏移  | 内容                              |
|------------------|-------|-----------------------------------|
| `VCPU_R0`        | 0     | x0-x30 guest GPRs（31×8=248 B）  |
| `VCPU_SP_EL1`    | 248   | guest SP_EL1                      |
| `VCPU_ELR`       | 256   | guest PC（ELR_EL2）              |
| `VCPU_SPSR`      | 264   | guest PSTATE（SPSR_EL2）         |
| `VCPU_HOSTCTX`   | 272   | host callee-saved+SP（13×8=104B）|
| `VCPU_SYSREGS`   | 376   | guest EL1 系统寄存器（128 B）    |

### include/aarch64/stage2.h
Stage-2 MMU API。`GUEST_RAM_BASE=0x40000000`（1GiB），`GUEST_RAM_SIZE=0x08000000`（128 MiB）。

### kernel/mm/aarch64/stage2.c
Stage-2 页表实现（identity map，IPA=PA）。

- 三级 LPAE：L1(4×1GiB) → L2(512×2MiB block) → L3(可选4KB精细页)
- `VTCR_EL2`：T0SZ=32、SL0=1、TG0=4K、SH0=IS、PS=36bits
- `VTTBR_EL2`：VMID=1，根页表地址用 `virt_to_phys()` 转为物理地址

> **关键修复**：VTTBR_EL2 和 L1→L2 指针必须为**物理地址**，曾用虚拟地址导致 Stage-2 page fault。

### kernel/vmm/vmm.c
VM 管理（架构无关层）：`vm_create()` 初始化 Stage-2 + vCPU，`vcpu_task_create()` 封装 `task_create()`。

### kernel/vmm/aarch64/el2_run.c
VMM 主循环与 exit 分发：

| ESR.EC | 含义               | 处理                                        |
|--------|--------------------|---------------------------------------------|
| 0x01   | WFI/WFE trap       | advance PC 跳过，resume                     |
| 0x16   | HVC                | PRINT→每100次打印+yield；DONE→退出循环      |
| 0x24   | Stage-2 Data Abort | `stage2_restore()` 恢复写权限，guest 重试   |
| 其余   | 未处理             | 打印诊断，停止 VMM                          |

### kernel/vmm/aarch64/el2_vmcs.S
最核心的上下文切换汇编。

**`el2_enter_guest(vcpu)`**：保存 host ctx → 修改 HCR_EL2(TGE=0,VM=1,TWI=1) → 安装 guest_vec_table → 加载 guest 寄存器 → `eret`

**`el2_trap_exit`**：保存 guest 寄存器 → 恢复 HCR_EL2(TGE=1,VM=0,TWI=0) → 恢复 host VBAR → 恢复 host ctx → `ret`

> **VHE 关键点**：`msr vbar_el1` 在 E2H=1 时写入 VBAR_EL2；vcpu 指针通过 `tpidr_el2` 跨 eret 传递。

### kernel/vmm/aarch64/vcpu_ctx.S
Guest EL1 系统寄存器保存/恢复。使用 `_el12` 后缀访问真实 EL1 寄存器（VHE 下 `_el1` 访问的是 EL2 别名）。

### kernel/vmm/aarch64/guest_vec.S
Guest trap 向量表，`.align 11`（2KB），16 个 entry 均 `b el2_trap_exit`。

### apps/aarch64/guest_test.S
Guest EL1 无限循环：`WFI` → `HVC_PRINT(x0=1, x1=counter)` → 重复。

### apps/aarch64/el0_loop.S（新增）
EL0 用户态无限 yield 循环，不依赖文件系统：
- `SYS_YIELD(x8=1)` 每次让出 CPU
- 每 50 次 yield 调用 `SYS_WRITE(x8=20)` 打印 `[el0] loop tick (EL0)`

## 修改文件

### Makefile
- 修复 `else ifeq` 结构为独立的 `ifeq` 块（riscv64/x86_64 分支原先被 else 截断）
- AArch64 块新增：stage2.c、vmm.c、el2_run.c、el2_vmcs.S、vcpu_ctx.S、guest_vec.S、apps_el0_loop.o 编译规则

### kernel/main.c
AArch64 分支替换 busybox 为三线程测试：

```c
// Thread 1: EL2 内核线程
task_create("el2_loop", el2_loop_thread, NULL, 5);

// Thread 2: EL1 Guest vCPU
vm_create(&g_test_vm);
vcpu_task_create(&g_test_vm.vcpus[0], 5);

// Thread 3: EL0 用户进程
process_create("el0_loop", (uint64_t)el0_loop_program, 0x200000, 5);
```

三个特权级全部正常并发，无异常退出。

## QEMU 启动参数

```bash
qemu-system-aarch64 -cpu cortex-a76 -M virt,virtualization=on -m 2G -nographic \
  -kernel build/kernel_aarch64.bin
```

`virtualization=on` 必须开启，使 CPU 以 EL2 启动并支持 Stage-2 MMU。

## 调度说明

当前为**半抢占**模式：EL0 进程受时钟（10ms）强制抢占；EL2/vCPU 内核任务仅靠主动 `task_yield()` 协作调度。
